## 1. Purpose

Two arcade families are missing:

1. **Taito Type X / X⁺ / X² / X³ / X⁴ and NESiCAxLive** are Windows PCs. A dumped game is a **folder** (an executable, usually `game.exe`, plus DLLs and data). There is no DAT, no hash and no readable internal id: the **folder name is the title**. Only ES-DE has a folder for them (`type-x`). They do not run on ARM handhelds.
2. **Cave CV1000** sets are real MAME/FBNeo ROMs and are already identified, named and covered. The only gap: Batocera (and Knulli) have a `cave3rd/` folder that resolves to no system today, so Organizar walks it as a pile and would propose moving its sets to `fbneo/`.

The rule this item adds: **a system recognised only by where the user put it**. `typex` has no content rule at all, and Coverly never opens, hashes or uploads any byte inside a Type X game folder.

## 3. Goals and non-goals

**Goals**

- G1. New system `typex` («Taito Type X», arcade family) where each direct child folder of a `type-x`/`typex` system folder is one game, including ES-DE's directory-as-file pattern (`Chaos Code.exe/`).
- G2. Zero bytes read inside a Type X game folder, by any module (scan, fill, identify, dedupe, organize, audit, add-ons, gamelists), proven by a tripwire test.
- G3. Title from the folder name, with board markers (`(Type X)`, `(Type X2)`, `(type x)`, `for NesicaxLive`) moved to a board tag; launcher suffixes (`.exe`, `.bat`, `.lnk`, …) not part of the title.
- G4. Covers from ScreenScraper (system 112) and SteamGridDB, by name. No libretro-thumbnails folder.
- G5. New system `cave3rd` («Cave CV1000») modelled on `model2`: `MAME.dat` only, ordered after `mame`; a loose set still goes to `fbneo`; sets inside `cave3rd/` stay there.
- G6. Profiles: ES-DE → `type-x`; Batocera/Knulli → `cave3rd`; everything else Absent. Honest UI note: Type X is PC only.
- G7. Correct the wrong D16 premise («ningún frontend tiene carpeta para Cave»).

**Non-goals**

- Cave's Steam ports (plain Windows games: no `windows` system exists) and Deathsmiles II (already `mame` via `deathsm2`).
- A generic `pcarcade`/`teknoparrot` system (option B), RetroBat profile, Lindbergh/RingEdge/Namco ES3.
- Reading TeknoParrot `UserProfiles/*.xml` (research §1.3: possible, not needed now).
- Renaming Type X folders on disk (loaders depend on the exact name).
- Any loader integration, link or recommendation. Loaders may be **named** as facts in docs (TeknoParrot, JConfig), never in the UI, never linked.

## 6. UX and UI

The only visible changes: two new systems in every system list and picker, their shelves in the library, Organizar groups for `cave3rd/`/`type-x/` that are «already sorted», board tags on Type X titles, and one honest note.

**Design plan (reviewed against generic defaults).** This is not a new screen; it extends the shelf rule from brand §2 and batch 3 §9.1.

- Color: existing tokens only, `cr-text-secondary` for the note, the Buckram cap of the shelf rule unchanged. No warning colour: being PC-only is a fact about the world, not a fault.
- Type: the shelf name's own run (UI sans at `text-caption` in Organizar, the section label in the library); counts stay mono via existing classes. No new weights.
- Layout: `Taito Type X · Solo en PC; no funciona en portátiles ARM   12` — the note rides in the name's ellipsis run, so a narrow shelf cuts the note first, never the name.
- Motion: none. The note is static text.
- Board tag: the existing tag chip/text treatment for name tags (`Type X2`, `NESiCAxLive`); no new component.

Review: the generic default here would be an amber «Not supported» pill with a warning icon, or a tooltip-only hint. Both rejected: a pill reads as an error the user must fix and breaks the shelf rule; a tooltip hides the one fact a handheld owner needs. The chosen treatment reuses the one already approved for «Sin emulador», so the two notes read as one family. Accessible name: the rowheader label includes the note (as for `noEmulator`).

`cave3rd` gets no note: CV1000 runs through the MAME/FBNeo cores on ARM, but its performance on H700-class chips is unverified (research §4), and the UI never states unverified facts.

## 8. Data flow

1. **Scan** (`scan_library` → `scan_system`): the profile resolves `type-x/` (ES-DE) or `TYPEX`/`typex` (any profile; global alias) to `typex`. Depth-1 dirs → folder `RomEntry { is_dir: true, stem: folder name (suffix kept on ES-DE), ext: suffix or "" }`, size/date from the metadata tree summary. Depth-1 launcher files → file entries. Nothing below depth 1 is visited except by the tree summary (metadata only).
2. **Identify**: no DATs → no hashing, no `system_for_dat`; `unidentified(parse_name(stem))` gives title + board tag.
3. **Fill**: `ArtQuery { hash: None, by_name: true, path: None for typex }` → ScreenScraper (112, by `romnom`/title) and SteamGridDB (title). Libretro is skipped (no `libretro`). With no keys configured, the existing «source not configured» path applies.
4. **Gamelists** (ES-DE): entries `./Raiden IV (Type X)` / `./Chaos Code.exe` with the cleaned name.
5. **Dedupe**: `typex` units out of scope.
6. **Organizar**: `type-x/` and `cave3rd/` resolve → skipped as already sorted. A loose `mushisam.zip` → `fbneo/`. A loose `game.exe` → unknown, left in place.

## 9. Edge cases and failure modes

| Case | Behaviour |
|---|---|
| `type-x/` on a Batocera card | The global alias resolves it: already sorted, scanned as `typex`; Organizar never moves it; Absent folder → the shelf shows the PC-only note. Never moved to a created `TYPEX/`. |
| Loose `Raiden IV (Type X)/game.exe` in a pile | Not `typex` (no location evidence). Its files stay unknown and in place (D15 behaviour, research §5). |
| `type-x/Chaos Code.exe/` holding `Chaos Code.exe` | One folder game; title «Chaos Code»; ES-DE media stem `Chaos Code.exe`. |
| `type-x/King of Fighters XIII Climax for NesicaxLive/` | Title «King of Fighters XIII Climax», board tag `NESiCAxLive`. |
| `type-x/Homura (type x)/Game.exe` | Title «Homura», tag `Type X`. |
| Empty game folder | Still one entry (size 0); the user put it there. |
| A game folder holding `Updates/` or `DLC/` | Opaque: not children, counted in size. |
| Files named like keys/licences inside | Never read (P5), skipped by `is_key_material` name check where listings are filtered. |
| Cloud-only (dataless) files inside | Tree summary counts them from metadata via `MetaProbe`; nothing is downloaded. |
| Huge game (tens of GB) | Tree summary caps (`TREE_MAX_ENTRIES`/`TREE_MAX_DEPTH`) apply; nothing is read. |
| Same title twice (`Raiden IV (Type X)` and `Raiden IV.exe`) | Both listed; no dedupe (P15). |
| `MAME.dat` with `cave3rd` present | Still maps to `mame` (order tie). Test pins it. |
| `cave3rd/mushisam.zip` on ES-DE | The global alias resolves: already sorted, stays. |
| `cave3rd/game.bin` | `bin` not accepted (P12): not an entry, left in place. |
| Name with a `/` or reserved Windows char | Existing name handling; nothing new. |
