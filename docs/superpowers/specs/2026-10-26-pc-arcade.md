## 1. Purpose

Two arcade families are missing:

1. **Taito Type X / X⁺ / X² / X³ / X⁴ and NESiCAxLive** are Windows PCs. A dumped game is a **folder** (an executable, usually `game.exe`, plus DLLs and data). There is no DAT, no hash and no readable internal id: the **folder name is the title**. Only ES-DE has a folder for them (`type-x`). They do not run on ARM handhelds.
2. **Cave CV1000** sets are real MAME/FBNeo ROMs and are already identified, named and covered. The only gap: Batocera (and Knulli) have a `cave3rd/` folder that resolves to no system today, so Organizar walks it as a pile and would propose moving its sets to `fbneo/`.

The rule this item adds: **a system recognised only by where the user put it**. `typex` has no content rule at all, and Coverly never opens, hashes or uploads any byte inside a Type X game folder. Only names leave the machine (the folder name as a ScreenScraper/SteamGridDB query, and only with the user's own keys), as for every other game.

## 3. Goals and non-goals

**Goals**

- G1. New system `typex` («Taito Type X», arcade family) where each direct child folder of a system folder that resolves to `typex` is one game, including ES-DE's directory-as-file pattern (`Chaos Code.exe/`).
- G2. Zero bytes read inside a Type X game folder, by any module (scan, identify, fill, dedupe, organize, audit, add-ons, gamelists), proven by a tripwire test (§10). Metadata (names, sizes, dates) is read; file contents never are.
- G3. Title from the folder name: board markers (`(Type X)`, `(Type X2)`, `(type x)`, `for NesicaxLive`) never reach the title, the art query or the gamelist name; launcher suffixes (`.exe`, `.bat`, `.lnk`, …) are not part of the title. The folder on disk is never renamed.
- G4. Covers from ScreenScraper (system 112) and SteamGridDB, by name. No libretro-thumbnails folder.
- G5. New system `cave3rd` («Cave CV1000») modelled on `model2`: `MAME.dat` only, ordered after `mame`; a loose set still goes to `fbneo`; sets inside `cave3rd/` stay there.
- G6. Profiles: ES-DE → `type-x`; Batocera/Knulli → `cave3rd`; everything else Absent. Honest UI note on the library shelf: Type X is PC only.
- G7. Correct the wrong D16 premise («ningún frontend tiene carpeta para Cave») and the batch 1 note «no ScreenScraper id found» for Type X, where they live (spec and `systems.toml` comment).
- G8. Nothing changes for installed users who have neither folder: same plans, same caches (no `FACTS_VERSION` bump, P18), same art paths.

**Non-goals**

- Cave's Steam ports (plain Windows games: no `windows` system exists) and Deathsmiles II (already `mame` via `deathsm2`).
- A generic `pcarcade`/`teknoparrot` system (option B), RetroBat profile, Lindbergh/RingEdge/Namco ES3.
- Reading TeknoParrot `UserProfiles/*.xml` (research §1.3: possible, not needed now).
- Renaming or moving Type X folders on disk (loaders depend on the exact name).
- Recognising a Type X folder outside a `typex` system folder (no `game.exe` heuristic).
- Fixing the ES-DE media folder name for systems whose folder differs from the id (batch 1 §13, owner question; P8).
- Any loader integration, link or recommendation. Loaders may be **named** as facts in docs (TeknoParrot, JConfig), never in the UI, never linked.

## 6. UX and UI

The only visible changes: two new systems in every system list and picker (except P19's manual choice for `typex`), their shelves in the library, `cave3rd/` and `type-x/` counted as already sorted in Organizar, cleaner Type X titles in the game sheet, the art queries and gamelists, and one honest note.

**Design plan (reviewed against generic defaults).** This is not a new screen; it extends the shelf rule from brand §2 and batch 3 §9.1.

- Color: existing tokens only, `cr-text-secondary` (`section-row__note`) for the note, the shelf rule unchanged. No warning colour: being PC-only is a fact about the world, not a fault.
- Type: the shelf name's own run; counts stay mono via existing classes. No new weights.
- Layout: `Taito Type X · Solo en PC; no funciona en portátiles ARM   12`. The note rides in `section-row__name`'s ellipsis run, so a narrow shelf cuts the note first, never the name. The note is longer than «Sin emulador»; at 360 px the name must stay whole and the count visible (E2E check).
- Motion: none. The note is static text, so reduced motion needs nothing.
- Accessibility: the rowheader's `aria-label` includes the note (`layouts.groupCount` with `group = "${name} ${note}"`, as for `noEmulator`); the middle dot stays `aria-hidden`. The note is real text, so it zooms and reflows with the label.

Review: the generic default here would be an amber «Not supported» pill with a warning icon, or a tooltip-only hint. Both rejected: a pill reads as an error the user must fix and breaks the shelf rule; a tooltip hides the one fact a handheld owner needs and is unreachable by touch and keyboard. The chosen treatment reuses the one already approved for «Sin emulador», so the two notes read as one family.

`cave3rd` gets no note: CV1000 runs through the MAME/FBNeo cores on ARM, but its performance on H700-class chips is unverified (research §4), and the UI never states unverified facts.

## 8. Data flow

1. **Scan** (`scan_library` → `scan_system`): the profile resolves `type-x/` (ES-DE) or `TYPEX`/`typex`/`type-x` (any profile; global alias) to `typex`. Depth-1 dirs (after the skips of P4) → folder `RomEntry { is_dir: true, stem: folder name (suffix kept only on ES-DE), ext: suffix or "" }`, size/date from the metadata tree summary. Depth-1 launcher files → file entries. Nothing below depth 1 is visited except by the tree summary (metadata only).
2. **Identify**: no DATs → no hashing, no `system_for_dat`; `parse_name(title_stem)` gives the cleaned title.
3. **Fill**: by name → ScreenScraper (112, `romnom`/title, `flyer` covers per P11) and SteamGridDB (title). Libretro is skipped (no `libretro`). Without keys, the existing «source not configured» path applies. Art is written at the profile's paths (P8 limitation on ES-DE).
4. **Gamelists** (profiles with `gamelist = true`): entries `./Raiden IV (Type X)` / `./Chaos Code.exe` with the cleaned name.
5. **Dedupe**: `typex` units out of scope.
