## 1. Purpose

After part C a game folder's `Extras/` is a number in a read-only cell: «Extras · 14 archivos». The user cannot see what is in it, add a soundtrack, tag the boss theme, open the manual or play a trailer, and Organizar leaves a PS3 theme, a Vita theme PKG or an Xbox 360 gamer-picture pack in the pile, or files it as a DLC.

Part D delivers:

1. **Official extras detected and placed by Organizar** (dry run, apply, undo), without keys: PS3 `.p3t` themes and theme/avatar PKGs, Vita theme PKGs (`0x1F`), PSP `.PTF` themes, Xbox 360 STFS themes, gamer pictures, avatar items and videos (by content type), 3DS soundtrack and video `.cia` apps. Retro has no official extras: music rips (SPC, NSF/NSFe, GBS, VGM/VGZ, PSF family) are linked by their own tags and suggested into `Soundtrack/` as **user** content.
2. **Extras CRUD in the game panel**: list by category; add (file picker and drag and drop onto the panel), rename, move between categories, send to the Trash; create, rename and remove own categories; tag each file. Every write is a journaled job with **undo**; nothing is deleted permanently.
3. **`extras.json`** inside `Extras/`: per file type, official or user, origin and tags; reconciled on read against files moved or renamed outside the app; never loses a tag silently; a malformed file is kept as a backup and reported.
4. **In-app player and viewer**: audio and video playback, image viewer, PDF viewer (and plain text), served through the Tauri asset protocol with per-file grants inside the open library only, keyboard accessible, reduced-motion aware.
5. **A sync flag per category** in the model only (off by default) for block 4. No sync is built.

The standing rules carry over unchanged: **keys are untouchable** (never read, include, download or decrypt; never link or recommend emulators, ROM or key sites), **nothing is overwritten**, **every change is undoable**, **the webview never sends a path** for a library write.

## 2. The owner's asks (verbatim from `TODO.md` §2.1)

> ### Carpetas fijas y `Extras/` libre (decidido con Miguel, 2026-11-01)
>
> - **Carpetas fijas del juego:** `Updates/`, `DLC/`, `Mods/`, `Cheats/`, `Extras/` y `Saves/`. Siempre con ese nombre y en ese sitio, porque de ellas dependen la organización automática, la traducción a cada emulador (4) y las partidas (5). El usuario no crea carpetas nuevas a ese nivel; la interfaz las muestra traducidas.
>
> **`Extras/`, semiautomática:**
>
> ```
> Juego/Extras/
>     Soundtrack/   ← oficial detectado (p. ej. el .cia de banda sonora en 3DS) + canciones del usuario
>     Manuals/      ← manual electrónico oficial + escaneos
>     Artwork/      ← arte oficial, escaneos de caja y cartucho, fan art
>     Videos/       ← tráileres, partidas grabadas
>     Themes/       ← temas y avatares oficiales (PS3/Vita/PS4/3DS)
>     Guides/       ← guías, mapas, PDF
>     (del usuario) ← categorías que el usuario crea desde la app
> ```
>
> - **Lo oficial se detecta y se coloca solo** (banda sonora, manual, temas y avatares distribuidos como paquete del sistema).
> - **Lo del usuario se gestiona desde la app (CRUD):** añadir, renombrar, mover y borrar con deshacer, arrastrar y soltar en la ficha del juego, crear categorías propias dentro de `Extras/` y etiquetar cada archivo («tema del jefe final», «versión orquestal»).
> - **`extras.json` junto a las carpetas:** tipo (audio, vídeo, imagen, documento), oficial o del usuario, origen y etiquetas, para buscar y filtrar aunque se muevan archivos; la app reproduce audio y vídeo y muestra imágenes y PDF.
> - **Sincronizar:** `Extras/` no se copia al dispositivo por defecto (casi ningún frontend la usa y ocupa espacio); se puede activar por categoría (p. ej. solo `Manuals/`).
>
> Tareas:
>
> - [x] Detectar y colocar mods, parches de traducción, trucos, licencias y extras oficiales por sistema (según la investigación de abajo). … los extras oficiales van con el CRUD de `Extras/` (parte D).
> - [ ] CRUD de `Extras/` en la ficha del juego: categorías sugeridas y propias, etiquetas, arrastrar y soltar, deshacer.
> - [ ] `extras.json` con tipo, origen y etiquetas; reproductor de audio y vídeo y visor de imágenes y PDF en la app.
>
> ### Investigación de mods, trucos, licencias y extras por sistema
>
> - **Extras oficiales:** solo existen en algunos sistemas: temas `.p3t` y PKG de tema/avatar en PS3, PKG de tema (`0x1F`) en Vita, temas `.PTF` en PSP, paquetes STFS de Xbox 360 (temas, imágenes de jugador, avatares; clasificables por su tipo de contenido sin claves). Los manuales electrónicos van **dentro** del juego en 3DS, Wii U, Switch y Vita (se muestran como parte del juego, no se separan). Cartucho y disco retro no tienen extras oficiales: ahí `Extras/` es del usuario, con sugerencias por las etiquetas de los rips de música (SPC ID666, NSF, GBS, VGM GD3, PSF).

Workflow brief for this run (part D): fixed suggested categories on disk in English (`Soundtrack/`, `Manuals/`, `Artwork/`, `Videos/`, `Themes/`, `Guides/`) plus user categories **inside** `Extras/` (never new folders at the game-folder level); official ones detected and placed by Organizar with dry run, apply and undo; panel CRUD with every write journaled and undoable, delete to the system Trash or undoable, never a silent permanent delete; `extras.json` inside `Extras/`, robust to outside moves and renames, malformed JSON preserved and reported; asset protocol scoped to the library roots only with a tight CSP; keyboard accessible, reduced motion; sync flag per category in the model only; build on part C's panel group and visual language.

## 4. Decisions

| # | Topic | Decision | Why |
|---|---|---|---|
| D1 | Categories on disk | `ExtrasCategory::{Soundtrack, Manuals, Artwork, Videos, Themes, Guides}` with `dir_name()` exactly those English names and `from_dir_name` case-insensitive exact (like `FixedFolder`). **User categories** are any other direct sub-folder of `Extras/`. Names are validated with `write::safe_file_name`, trimmed, NFC, at most 64 characters, no leading dot, not `extras.json`, not equal (case-insensitively) to a fixed category or to another user category. Only one level: files may sit deeper inside a category (shown with their sub-path), but the app creates no sub-folders. Files directly in `Extras/` are shown as «Sin categoría» and can be moved into one. Fixed categories cannot be renamed or removed from the app; they are created only when something goes in (part A D4) and are shown as empty drop slots before that. The game-folder level is never written except to create `Extras/` itself. | Brief; one rule shared by Organizar, the panel and block 4. |
| D2 | `extras.json` location and shape | `Extras/extras.json`, UTF-8, pretty-printed, sorted keys for stable diffs: `{ "version": 1, "categories": { "<dir name>": { "sync": false } }, "files": [ { "path": "Soundtrack/01 Opening.flac", "type": "audio" \| "video" \| "image" \| "document" \| "other", "provenance": "official" \| "user", "origin": { "how": "organize" \| "added" \| "found", "format"?: "ps3-p3t" \| "ps3-theme-pkg" \| "ps3-avatar-pkg" \| "vita-theme-pkg" \| "psp-ptf" \| "x360-theme" \| "x360-gamerpic" \| "x360-avatar" \| "x360-video" \| "3ds-soundtrack-cia" \| "3ds-video-cia" \| "spc" \| "nsf" \| "gbs" \| "vgm" \| "psf", "from_name"?: "<original file name>", "rip"?: { "game"?, "title"?, "artist"? } }, "tags": ["tema del jefe final"], "size": 123, "mtime_ns": 0, "added_at": "<RFC 3339>" } ] }`. `path` is `/`-separated, relative to `Extras/`, compared by components. `type` is derived from the extension (§6.3); `other` is added to the owner's four for packages (`.p3t`, `.pkg`, STFS, `.cia`, `.PTF`) and anything unknown. `sync` defaults to `false` for every category (block 4 reads it; no UI in part D). Unknown fields are kept on rewrite (`serde_json::Value` passthrough per record and at top level) so a newer build's data survives an older build's edit of the same version. | Brief fields; forward-safe. |
| D3 | When `extras.json` is written | **Opening the panel never writes.** Listing reads and reconciles in memory (D4). The file is written only as part of a user write (add, rename, move, trash, tags, categories) or an Organizar apply that places extras, always inside the same journaled job: `Op::Created` the first time, `Op::Replaced { backup }` after (the journal's backup is the previous file, so undo restores it byte for byte). Written atomically (temp in `Extras/` + `rename_noclobber`-style replace through the writer). A game without any record and without user tags never gets an `extras.json` from a plain read. | Read-only volumes and SD cards are opened often; no surprise writes. |
| D4 | Reconcile (robust to outside moves) | On every listing: walk `Extras/` (regular files, depth ≤ 4, no symlinks followed, `is_skipped_entry`, hidden files and `extras*.json` excluded, cap 10 000). Match records to files in order: (1) same `path` by components; (2) for each unmatched record, an unmatched file with the same `size` and `mtime_ns` (a move or rename on one volume keeps both); exactly one candidate → matched as **moved**, more than one → no match; (3) same file name and size in another category → moved. Matched records carry their tags, provenance and origin to the new path. Unmatched files become implicit `user` records with `origin.how = "found"` and no tags. **Unmatched records are never dropped**: they are listed as «No encontrados» with their tags and two actions, «Buscar de nuevo» (re-list) and «Olvidar» (a journaled write that removes the record; undoable). The reconciled view is persisted only by the next write (D3). | Brief «nunca perder etiquetas sin avisar». |
| D5 | Malformed or newer `extras.json` | **Malformed** (not JSON, wrong shape, or a record without a valid `path`): the panel shows a warning Alert «No se puede leer extras.json. Las etiquetas guardadas no se muestran; el archivo no se ha tocado.» and lists files from disk as `found`. The first write afterwards first **copies** the bad file to `Extras/extras.broken-<YYYYMMDD-HHMMSS>.json` (never overwriting: a numeric suffix on collision; journaled `Created`), then writes a fresh file; the Alert then names the backup. Records that parse individually are salvaged when the top level is an object with a `files` array (bad records are skipped and counted in the Alert). **Newer** (`version` > 1): read what is understood, show «extras.json es de una versión más nueva de Coverly; aquí solo se puede ver», and **disable every write** for that game (file operations included, because they must update the json). A file over 8 MiB is treated as malformed (never parsed). | Brief; never overwrite what we cannot understand. |
| D6 | Official extras by system (Organizar) | Detected in the addon walk hook (part B) **before** the game probes claim the file, only for these, always from plaintext headers and never from a file `is_key_material` names: **PS3** `.p3t` (magic `P3TF`) → `Themes/`; PS3 PKG (type 1) whose metadata `content_type` (metadata entry id `0x02`, plaintext, read through the metadata table at the header's `metadata_offset`, at most 64 entries and 4 KiB) is `0x09` (theme) or `0x0D` (avatar) → `Themes/`; **Vita** PKG (type 2) with `content_type` `0x1F` → `Themes/`; **PSP** `.PTF` (file magic `PTF` / extension) → `Themes/`; **Xbox 360** STFS by content type: `0x00030000` theme, `0x00020000` gamer picture, `0x00009000` avatar item → `Themes/`; `0x00090000` video, `0x000C0000` trailer, `0x00100000` movie, `0x00300000` music video, `0x00400000` game video → `Videos/`; **3DS** `.cia` of a `00040000` application whose SMDH title (decrypted files only) or file name contains a soundtrack word (`soundtrack`, `sound track`, `OST`, `サウンドトラック`, `banda sonora`) → `Soundtrack/`, or a video word (`trailer`, `video`, `tráiler`) → `Videos/`. Everything else stays as today (a 3DS CIA without such a word is a game; a PS3 PKG of another type is DLC/GameData). Content-type tables live in one place each (`consoles/sony.rs` `PkgContentType`, `consoles/xbox.rs` `content_kind`). | The research's list, no keys. The PS3 values are «medium» in the research: they are pinned by fixtures and the plan note always shows the type («Tema (tipo de contenido 0x09)») so the dry run makes a wrong guess visible before anything moves; §15 Q3. |
| D7 | Linking an official extra to its game | Same resolver as part B (`addons/link.rs`), in this order: (1) **filed under**: it sits in a pile game folder (or its `Extras/`) or beside the game's file with the same stem; (2) **title id**: STFS `0x360` title id equal to a game's title id (Xbox 360 extras carry the game's id); a PS3 PKG content id's title id equal to a game's; (3) **title key** of the display name (STFS `0x411`, 3DS SMDH title, `.p3t` XML `name` when present, else the file stem with tags stripped) equal to exactly one game's title key in the same system (pile or library, `LibraryIndex`). Ambiguous or none → **left in place** with `LeftReason::ExtraWithoutGame { category }` («Tema sin juego: no se sabe de qué juego es»), never guessed. Vita themes usually carry their own title id, so they link only by (1) or (3). | Never guess; part B's rule. |
| D8 | Delete | «Mover a la papelera» uses `TrashBackend` with the existing `ArchiveTrash` / `ArchiveTrashed { trash }` ops, so undo brings the file back from the exact Trash location. When the volume has **no Trash** (`available() == false`, e.g. some FAT SD cards on macOS), the file is moved to `<library root>/.coverly-trash/<job id>/<rel path>` (journaled `Moved`, hidden and skipped by scan, Organizar and Duplicados), and the confirmation says so before acting: «Este disco no tiene papelera. Los archivos se guardan en .coverly-trash dentro de la biblioteca hasta que los borres tú.» A failure of both never deletes: the file stays and the error is shown. Removing a **user category** that holds files trashes its files the same way and then removes the empty folder (`Removed`, recreated on undo); an empty one is just removed. There is no permanent delete anywhere in the app. | Brief «nunca un borrado definitivo silencioso». |
| D9 | Scan count | `count_fixed` for `Extras/` excludes `extras.json`, `extras.broken-*.json` and `.coverly-trash` (the latter is at the library root, already hidden). Part C's D9 count otherwise unchanged. | The cell must count the user's files. |
| D10 | Writes are jobs | New `JobKind::Extras` (kebab `"extras"`; builds older than part D list such a job as unreadable and never undo it by halves, as with `dedupe`). **One panel action = one job** (a multi-file move is one job), carrying the game folder as `root` and, for adds, no source root (sources are read, never moved: D13). Ops: add = `Copied { from }` + `DirCreated` for `Extras/` and the category when new; rename/move = `Moved { via: Rename }` on the same volume (always: the game folder is one volume); trash = `ArchiveTrash`/`ArchiveTrashed` or `Moved` (D8); category create/rename/remove = `DirCreated` / `DirMoved` / `Removed`; tags and «Olvidar» = the json op only. Every job ends with the json op (D3). The result returns the job id and the new listing. Undo is the existing `undo_job` (the toast's «Deshacer», `Cmd/Ctrl+Z` in the section, and the jobs history); the existing `later_jobs` rule keeps a later job's files safe. Extras writes take the library's existing write lock, so they never run beside an Organizar, fill or Duplicados apply on the same library (the panel shows the existing busy reason). A read-only volume disables every write with the existing read-only reason. | One undo path for the whole app. |
| D11 | Drag and drop | Two kinds. **(a) From the OS onto the panel**: Rust records each window `DragDrop::Drop` in the session as a **drop token** (`{ token, paths, at }`, last 4 kept, 2 minutes) and emits `extras://drop` with the token, the drop position and, per path, only `{ name, size, is_dir }`. The webview hit-tests the position against the panel's category drop zones and calls `extras_add_dropped(entry_id, category, token)`; Rust copies only those recorded paths. `onFolderDrop` ignores a drop whose position falls inside the Extras section, so dropping music never also opens a library. Folders dropped are added file by file (depth ≤ 2, max 500 files, no symlinks); key material and hidden files are skipped and counted («2 archivos de claves no se añaden»). **(b) Inside the panel** (moving a file to another category): pointer-event dragging, not HTML5 drag and drop, because Tauri's window drag-drop handler disables HTML5 DnD in WebView2 on Windows. Every drag has a keyboard and menu equivalent: «Mover a…» (submenu of categories) and, on a focused row, `Alt+↑/↓` moves to the previous/next category (announced). | Paths come from the OS, never from the webview; DnD works on all three platforms. |
| D12 | Serving media | `tauri` gains the `protocol-asset` feature; `app.security.assetProtocol = { "enable": true, "scope": { "allow": [], "deny": ["**/*.rap", "**/*.rif", "**/*.edat", "**/act.dat", "**/*.tik", "**/ticket.db", "**/seeddb.bin", "**/*.keys", "**/keys.txt", "**/otp.bin", "**/kv.bin", "**/work.bin", "**/.*"] } }`: the static scope allows **nothing**. `extras_media(entry_id, file_id)` resolves the file from the session listing, canonicalises it, checks it is a regular file under the game's canonical `Extras/` inside the open library root (a symlink pointing out is refused), is not key material, then grants **that one file** with `asset_protocol_scope().allow_file(path)` and returns `{ src_path, mime, kind }` for `convertFileSrc`. Grants are per file and per process; switching library grants nothing new outside the new root. The CSP becomes `default-src 'self'; img-src 'self' data: blob: asset: http://asset.localhost; media-src 'self' asset: http://asset.localhost; style-src 'self' 'unsafe-inline'; font-src 'self' data:; connect-src 'self' ipc: http://ipc.localhost asset: http://asset.localhost; worker-src 'self'; object-src 'none'; frame-src 'none'; base-uri 'none'` — no `unsafe-eval`, no `wasm-unsafe-eval`, no frames. The asset protocol already answers `Range` requests, so video seeks without loading the whole file. | Brief: scoped to the library only, tighter than a whole-root grant; CSP stays tight. |
| D13 | Adding files | **Copy**, never move: the user's source stays where it was (undo removes the copy only if unchanged since, by fingerprint). Picker: `extras_add_pick(entry_id, category)` opens the native multi-file dialog **from Rust** (`tauri-plugin-dialog` Rust API), so no path crosses the bridge. Name collisions: never overwrite; the copy gets ` (2)`, ` (3)`… before the extension, and the result says so. Each copy is verified (size + CRC32 while copying, `transfer.rs`). Limits per action: 500 files and 20 GiB; above, nothing is copied and the panel says why. Free-space check before copying (existing `transfer` helper); not enough → nothing copied. The target category: the drop zone or the category the «Añadir» button belongs to; from «Añadir» at the top, the **suggested** category by type (audio → Soundtrack, video → Videos, image → Artwork, PDF/text → Guides, `.pdf` whose name says manual/manuel/handbuch/manuale/説明書 → Manuals, packages → Themes), shown and changeable in a small confirmation step before copying. Music rips get their tags read (D15) and the game-title match shown («Etiqueta SPC: Super Metroid»). | Safest default; Q1. |
| D14 | Rename | Edits the **stem** only; the extension is kept (a changed extension would change the type and break playback). Same validation as D1 names (255 bytes, `WINDOWS_MAX_PATH` checked for the full path on every OS so the library stays portable). Collision → refused with the reason, never auto-suffixed (the user typed that name). | |

## 8. UX/UI design

### 8.1 Design plan (frontend-design pass, reviewed against generic defaults)

The subject is the same librarian's catalogue as part C: physical games on shelves, each with its box contents. Extras are the **inserts in the box** — the soundtrack CD, the manual, the poster. The audience is a collector tidying their own library; the section's primary job is to see what a game comes with and put new things in the right place quickly.

- **Colour (existing tokens only, no new palette):** Greyboard surfaces (`--cr-surface` #fbfbf9, `--cr-surface-sunken` #e7e9e3) for category bands; Buckram (`--cr-primary` #0e5e6f, `--cr-buckram-3` #dcebec) for the active drop zone and the playing row; Manila (`--cr-manila-3` #fbedcd, `--cr-manila-11` #8a5f12) only for the «Oficial» mark, kept tiny (the brand's ~2 % rule; Manila already means «found by the app»); semantic `--cr-warning` / `--cr-warning-bg` for «No encontrados» and the malformed-json Alert. Dark mode through the semantic tokens.
- **Type:** Atkinson Hyperlegible Next 13 px for names and labels; Atkinson Hyperlegible Mono for sizes, durations, times, page numbers and on-disk folder names (`Soundtrack/`), because they are data; Archivo only for the viewer's title (the one accent, as part C spends it on the version number).
- **Layout:** in the panel, after «Mods, trucos, extras y partidas», a section «Extras» (`h3`, count in mono). Categories are stacked bands, each a header row (translated name, `Soundtrack/` in mono secondary, count, «Añadir» icon button) over its file rows. A file row: type glyph (16 px line icon), name (truncate middle, full in `title`), tag chips on a second line when present, size in mono right-aligned, row menu. Empty suggested categories collapse into **one line of dashed slots** («Banda sonora», «Manuales»… as small dashed chips), the app's missing-slot mark: they are drop targets and buttons («Añadir a Manuales»). User categories follow the fixed ones, alphabetically, then «Sin categoría», then «No encontrados». The mini player is a 48 px band pinned to the bottom of the panel's scroll area. Left-aligned throughout.

```
Extras  14
┌ Banda sonora   Soundtrack/      12  [+] ┐
│ ♪ 01 Opening.flac                 4,1 MB │
│   tema del jefe final  versión orquestal │
│ ♪ 02 Boss.flac          ▶ playing  3,8 MB │
├ Temas y avatares   Themes/   1  Oficial ─┤
│ ◇ Tidewalker Theme.p3t           2,0 MB │
└──────────────────────────────────────────┘

┌──────────────────────────────────────────┐
│ ▮▮  02 Boss.flac · Tidewalker  1:12 / 3:40 ═══○──── │
└──────────────────────────────────────────┘
```

- **Viewer:** a Dialog at up to 90 vw × 90 vh on `--cr-surface-sunken`, image centred on a quiet checkerboard (transparency is information for artwork), header with the file name (Archivo), category and «3 de 12» in mono, footer toolbar (prev/next, zoom, page, «Abrir con otra app», «Mostrar en la carpeta»). PDF pages stacked vertically with a page counter.
- **Motion:** only responses to actions: the drop zone's Buckram fill fades in on drag-over (`--cr-duration-fast`, `--cr-ease-standard`); the viewer opens with a 120 ms fade (no scale); a moved row is briefly outlined in Buckram where it lands (`--cr-duration-base`). All zeroed by the reduced-motion token override and `useReducedMotion` (no smooth scroll, no fade). No equaliser animation, no progress shimmer.

Review against generic defaults (changes made): no card per file (the «SaaS-card kit»: files are rows in a band, like a box's contents list); no big drop-zone rectangle with a cloud icon (the generic uploader: the drop targets are the categories themselves, using the app's dashed-slot language); no all-caps category eyebrows (sentence-case translated names, the disk name in mono beside it, which is real information, not decoration); no middle-dot meta strings except the player line where it separates track and game; no coloured «Official» pill on every row (one small Manila mark on the category header when it holds official files, and the row's menu says «Oficial: tema de PS3» in text); no full-screen black lightbox (the viewer stays on the app's surfaces so artwork colours read true in both themes).

### 8.2 States

- **No `Extras/` yet:** the section shows the six dashed slots and «Arrastra aquí la banda sonora, los manuales o el arte de este juego, o usa Añadir.» plus «Añadir archivos».
- **Loading:** the section keeps its last listing and shows a small spinner in the header (no skeleton flash under 300 ms).
- **Read-only volume / busy / newer json:** writes disabled, one line with the reason; play and view still work.
- **Malformed json:** warning Alert (D5) above the list; writes allowed (they back up first).
- **Missing records:** «No encontrados (2)» band in warning tone with their tags and «Buscar de nuevo» / «Olvidar».
- **Large libraries:** more than 200 files in a category → the category virtualises its rows (existing virtual list helper) and starts collapsed.

### 8.3 Interactions

- **Add:** header «Añadir archivos» or a category's «+» → native picker (Rust) → `ExtrasAddDialog` lists what will be copied, the category per file (changeable, suggested by type and rip tags), rip tag suggestions as tag buttons, the total size, then «Copiar 5 archivos». Drop on a category skips the dialog when every file's type fits the category, else shows it.
- **Rename:** menu «Renombrar» or `F2` → inline input on the stem, extension shown as fixed mono suffix; `Enter` saves, `Esc` cancels.
- **Move:** pointer drag a row onto another category band (the band highlights; a ghost row follows the pointer; `Esc` cancels), menu «Mover a…», or `Alt+↑/↓`.
- **Trash:** menu «Mover a la papelera» or `Delete`/`Backspace` (with selection) → AlertDialog only for more than 1 file or when the disk has no Trash; a single file goes straight to the Trash with the undo toast.
- **Tags:** menu «Etiquetas…» or `T` → Popover with input + chips; `Enter` adds, `Backspace` on empty input removes the last chip; suggestions below.
- **Selection:** click selects one, `Cmd/Ctrl+click` toggles, `Shift+click` ranges within a category; `Space` toggles the focused row; a bulk bar appears: «3 seleccionados · Mover a… · Etiquetar · Papelera».
- **Categories:** «Nueva categoría» → inline input in a new band; own category header menu: «Renombrar», «Quitar categoría» (AlertDialog when it has files: «Quitar «Remixes» y mover sus 4 archivos a la papelera»).
- **Undo:** each write shows a toast «Movido a la papelera: 02 Boss.flac» with «Deshacer»; the toast lasts 10 s and does not dismiss while focused or hovered; `Cmd/Ctrl+Z` inside the section undoes the last Extras job of this game.
- **Play/view:** `Enter` or double-click on a row; audio row also has a play button. Viewer keys: `←/→` previous/next file, `Esc` close, `+`/`-`/`0` zoom (image, PDF), `PageUp/PageDown`/`Home`/`End` (PDF pages), `Space` play/pause (video/audio focus). Mini player: play/pause, previous/next, seek Slider (Radix, arrow keys ±5 s, PageUp/Down ±30 s), time in mono, «Detener», game name button that selects the game.

### 8.4 Accessibility

- The section is a `region` named «Extras»; each category is a group (`role="group"`, `aria-labelledby` its header) with a list of rows; rows are focusable (roving tabindex across the section, `↑/↓` between rows, `Home/End`), each with an accessible name «01 Opening.flac, audio, 4,1 MB, etiquetas: tema del jefe final» and «oficial» when it is.
- Every pointer drag has a keyboard path (D11 b); drop zones are also buttons («Añadir a Manuales»).
- Live region (polite): results of writes («Movido a Vídeos», «Copiados 5 archivos a Banda sonora»), moves by keyboard, player track changes. Errors use an Alert, not only a toast.
- Focus: after trash, focus moves to the next row (or the category header); after rename, back to the row; the viewer traps focus and returns it to the row on close.
- Media: native `<video controls>` (keyboard and captions tracks if the file has them); the mini player's buttons have names («Pausar», «Siguiente pista»); no autoplay of video; nothing flashes.
- Contrast: Manila «Oficial» mark text uses `--cr-manila-11` on `--cr-manila-3` (≥ 4.5:1, checked in E2E in both themes); warnings use the semantic tokens; focus ring `--cr-border-width-focus`; forced colours: dashed slots and drop highlight use `CanvasText`/`Highlight`.
- Reduced motion: D-plan motion off; PDF scroll-to-page uses `behavior: 'auto'`.

## 10. Edge cases and failure modes

| Case | Behaviour |
|---|---|
| File renamed in Finder inside `Extras/` | Reconcile step 2 matches by size + mtime; tags carried; json updated on the next write. |
| File copied (not moved) elsewhere and original deleted | mtime usually kept by copy tools → matched; else listed in «No encontrados» with tags, plus the copy as `found`; the user can «Olvidar». |
| Two identical files (same size and mtime) | No match by fingerprint (ambiguous); by name + size if unique; else both `found`, record in «No encontrados». Never a silent merge. |
| `extras.json` hand-edited with a bad record | Salvage the rest, count the bad ones in the Alert; backup on next write. |
| `extras.json` is a directory or a symlink | Treated as malformed; never followed; never overwritten (the write is refused with the reason). |
| Category folder is a symlink | Not followed: shown as a category with 0 files and the note «enlace, no se sigue»; writes into it refused. |
| A file in `Extras/` is a symlink pointing outside | Listed with an «enlace» mark, not playable, not movable (refused with reason); trash moves the link itself only. |
| Key material dropped or picked | Never copied, counted in the result. Never opened. |
| Name not valid on Windows (`CON.mp3`, trailing dot, `:`) | Refused for new names; existing files are listed and playable, rename offered. |
| Path over 259 UTF-16 units | Add/rename/move refused with the existing «path too long» reason on every OS. |
| Volume ejected mid-job | Existing journal resume/undo rules; panel shows the volume-gone state. |
| Source changed while copying | Verified copy fails, the partial target is removed (journal), nothing else touched. |
| Game folder renamed by Organizar later | `extras.json` moves with `Extras/` (paths are relative); no update needed. |
| Organizar places an extra where a same-named file exists | No-clobber suffix as everywhere; never overwritten. |
| Library opened as a non-`coverly-library` profile | Extras section shows only for game folders (part C rule); Organizar places extras only with game folders on. |
| Drop over the panel while a different game's panel is open | The hit-test uses the panel on screen; the token is used once. |
| Drop token expired or reused | `extras_add_dropped` refuses with «Vuelve a soltar los archivos.»; nothing copied. |
| Undo after the user edited the file | Existing fingerprint rule: kept, reported «conservado porque lo cambiaste». |
| Undo of a trash whose file was emptied from the Trash | Reported as not restorable; the json op still restores the record, which then shows in «No encontrados». |
| Audio playing when the library closes or the file is trashed | Player stops; if trashed via undo-able job, the player skips to the next track. |
| Huge PDF (>200 MB) or image (>100 megapixels) | Not opened in-app; «Abrir con otra app». |
| WebKitGTK without GStreamer codecs | `canPlayType` empty → unplayable view. |
| `extras.json` over 8 MiB | Malformed (D5). |
| More than 10 000 files in `Extras/` | Listing capped with «más de 10 000» like the count; writes on files past the cap impossible (not listed). |

## 11. Security

- No path from the webview reaches a write or a read: ids and the session's listing only; drop paths are recorded by Rust (D11); the picker runs in Rust (D13).
- Asset protocol: static scope empty, per-file grants after canonical checks (D12); deny globs for key names and dotfiles as a second fence.
- CSP tightened (`object-src 'none'`, `frame-src 'none'`, `base-uri 'none'`), no eval, pdf.js scripting off.
- Text files are rendered as text nodes; SVG only in `<img>`.
- Parsers (official sniff, rips, PKG metadata, json) are bounded and fuzzed with `proptest` against panics.
