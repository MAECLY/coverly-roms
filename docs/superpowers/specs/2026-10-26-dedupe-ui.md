# Coverly ROMs — Duplicates screen polish (Design Spec)

> Status: **Reviewed draft** (adversarial review against TODO.md and the code, §14) · Date: 2026-10-26 · Owner: Miguel Angel Esparza Calero (MAECLY)
> Roadmap item: TODO.md **1.5. Mejora de la interfaz de Duplicados**.
> Builds on [`2026-10-18-duplicates-design.md`](2026-10-18-duplicates-design.md) (the planner, the "shelf and tray" screen, §11). Nothing in the planner's grouping, keeper rules or apply changes here: this item adds **facts the planner already knows** to the plan view, **one read-only command** for covers, a **wider (still scoped) reveal** for Organise pile copies, and a **visual and keyboard pass** over the screen.
> Branch: `feat/dedupe-screen-polish`. The settings reorganisation (TODO 1.6) runs in parallel on `feat/settings-tabs`; this branch does not touch the settings screen.

## 1. Purpose

The duplicates screen tells you the truth, but it reads like a list of file names. When two copies are the same game, what you need to decide is the **region**, the **revision**, whether a copy has **your save**, what **format** it is in and what it **looks like**. Today the screen shows the file name, a size, a "Se queda" badge and one sentence of why. You cannot see the cover, you cannot open the copy in Finder before you decide, and you cannot tell at a glance why the shelf holds what it holds.

This item makes each copy readable at a glance and the screen pleasant to work through with the keyboard, without changing what Coverly decides or moves.

## 2. The owner's asks (verbatim from TODO.md 1.5)

> La pantalla «estante y bandeja» da la información, pero se queda simple. Mejoras:
>
> - **Mostrar en Finder / Explorador / gestor de archivos** para cada copia (la que se queda y las que se apartan) y para la carpeta `_Duplicados/` tras aplicar. En Tauri, `tauri-plugin-opener` (`revealItemInDir`) cubre macOS, Windows y Linux; texto según el sistema: «Mostrar en Finder», «Mostrar en el Explorador», «Mostrar en la carpeta».
> - **Etiqueta de región** en cada copia (USA, Europe, Japan, World…, con su bandera o código), sacada del nombre del catálogo o de las etiquetas del nombre del archivo (`NameTags`). Cuando las copias son el mismo juego, la región es lo que más ayuda a decidir; también revisión (`Rev 1`), idioma (`En,Fr,De`) y marcas de volcado (`[!]`, `[b]`, hack, traducción) como etiquetas.
> - **Portadas**: hoy la pantalla no muestra ninguna. Enseñar la portada de cada grupo (y de cada copia si tiene la suya), reutilizando las de la biblioteca y las de libretro-thumbnails; con hueco de portada claro cuando falte.
> - Más detalle por copia: tamaño, formato (zip, 7z, CHD, CUE/BIN), fecha de modificación, si tiene partida guardada y de cuándo, y por qué regla se eligió la que se queda.
> - Repaso visual con el skill de diseño: jerarquía entre el juego, la copia que se queda y las apartadas; estados (conflicto, solo informado, otra versión) más visibles; atajos de teclado para elegir copia y aplicar; animación al apartar en la línea de la landing.

The owner also said, for this run: reveal must use a **narrow** permission (only paths inside the library or the quarantine, never an arbitrary path from the webview) and be mocked in the browser backend; illustrated animations in the landing's style are welcome.

## 3. Goals and non-goals

### Goals

1. **Reveal** every copy (keeper and tray, including conflict copies and report-only copies) and the quarantine folder after apply, with an OS-specific label.
2. **Tags** on every copy: region(s), revision, languages, release class (beta, proto, demo, sample), dump flags (`[!]` verified, `[b]` bad, `[o]` overdump, `[a]` alternate), modification (hack, translation, trainer, fixed, pirate, unlicensed) and up to two other groups as written (`Virtual Console`, `Rumble Version`…), each marked with where it came from (catalogue name or file name).
3. **Covers**: one cover per group (the keeper's, else the first copy that has one, else an already downloaded libretro-thumbnails image of the catalogue name), plus a small thumbnail on a copy that has **its own** art different from the group cover. A clear missing-art slot (brand §2 "Missing" slot) when there is none. Duplicates screen only (see goal 6).
4. **Facts per copy**: size, format, modification date, save (present, how many, last written), times played when the frontend's game list says so, and a **rule chip** naming the rule that put the keeper on the shelf.
5. **Visual pass**: a clear hierarchy game → kept copy → set-aside copies; conflict, report-only and other-version states visible without reading; keyboard shortcuts to move between games, pick a copy, reveal and apply; one calm illustrated set-aside animation.
6. The same `DupGroup` keeps working in the Organise proposal (`pickable={false}`), where tags, facts and reveal also show. **Covers are not shown there**: Organise groups come from the `OrganizePlan` (`organize/plan.rs:761`, kept by `OrganizeManager`), not from a kept dedupe plan, so there is no dedupe `plan_id` to ask `dedupe_art` with; the pile rarely has art anyway. The cover column is simply absent (no empty slot) when `planId` is not passed.

### Non-goals

- Changing grouping, keeper rules, confidence, apply, undo or the plan format version.
- Downloading anything to show a cover. Covers come from disk (library art) or the existing downloaded-art cache, offline only.
- Restructuring Settings or moving the duplicates options (TODO 1.6, parallel branch). The «Ajustes de Duplicados» link from this screen is an explicit 1.6 task («enlaces directos desde cada pantalla»), so **this branch adds no settings link** (no `settingsLink` key, no `openSettings` call) to avoid two branches adding the same thing; there is no such link on `main` today.
- Flag emoji. See D3.
- A new screen or route. Everything happens inside `DuplicatesScreen`, `DupGroup` and its rows.
- Renaming or moving existing locale keys (other branches edit `locales/*.json` in parallel; moves turn into merge conflicts and break the parity test on merge).

## 5. Decisions (defaults for open questions)

| # | Question | Decision | Why |
|---|---|---|---|
| D1 | Add a reveal command or a plugin permission? | **Reuse `reveal_path`**, no new opener permission in `capabilities/default.json`. Rows call it with the copy's **current** location: `member.unit.primary` before apply, `member.dest` once that copy was moved to the quarantine (the job report says which moved), `primary` again after undo; nothing after a Trash apply. The result calls it with the quarantine. `revealable` gains the kept **Organise** plans' `source` and `target_root` (same component-wise rule), so pile copies in the Organise proposal can be revealed. Make `reveal_path` `async` + `blocking` like `read_art` (the opener talks to D-Bus on Linux and COM on Windows; a slow file manager must not freeze the window). | It is already scoped server-side to known roots and quarantines (`revealable`), which is exactly the owner's "never arbitrary paths" rule. Granting `opener:allow-reveal-item-in-dir` to the webview would widen the surface for nothing. |
| D2 | Where do tags come from? | **Core**, a new `Member.facts: MemberFacts` filled from the existing `UnitFacts`: regions, revision, class and languages from the catalogue name when level 2 knows the game, else from the file name; dump flags and modification are the **union** of both names (a `[b]` or `[T+Spa]` written only in the file name still shows). Each chip carries its own source (`from: catalogue \| file-name`), not one flag for the whole set. `unknown_groups` of the shown name become `other` tags (as written, at most 2 + overflow). | One parser, shared by the app, Organise and `coverly dedupe --report json`. TS never parses file names. Keeps the "names never group" rule intact: tags are display only, the keeper rules keep reading `UnitFacts.tags` unchanged. |
| D3 | Flag or code? | **Short code chip** from a fixed table covering all 19 `Region` values: `WLD USA EUR JPN ASI AUS BRA CAN CHN FRA GER HKG ITA KOR NLD ESP SWE TWN UK`. The localised full name (`regions.*`, already in both locales) is in the chip as visually hidden text (a `<span>` has no accessible name from `aria-label`), and in a hover tooltip. No flag emoji, no flag images. | Windows has no flag emoji (renders "US" letters), Europe and World have no flag, flags are political and noisy at 12 px. A mono code reads like a label-maker tag, which is the brand (brand §5 mono = "label-maker readout"). |
| D4 | Covers: map plan paths to library entries in TS, or ask Rust? | **Ask Rust by ids**: new command `dedupe_art(plan_id, group, member: Option<usize>, media) -> bytes`. The art paths are recorded **in the plan** at plan time (`MemberFacts.art`, D7), because the kept plan has no `Unit`s or profile to re-run `art_of` with. Rust reads the path from the kept plan, canonicalises it and requires it under the plan root's canonical form (same guard as `read_art`'s `inside_root`, so a symlinked art file cannot leak a file outside the library), caps at `MAX_ART_BYTES`, and returns the bytes; no art → `IpcError::ArtMissing` (`art-missing`), which the hook turns into the missing slot, never a toast. For `member = None` it resolves the group cover: keeper → first member with art in that media → an already downloaded libretro-thumbnails image of the catalogue name (D16). | Survives a library rescan (generation change), never compares path text in JS (Windows CI), and the webview never names a path. Reuses the library's own art files and the fill's download store, as asked. An `Option<tauri::ipc::Response>` is not a valid raw-bytes return, hence the error for "none". |
| D5 | Which media is "the cover"? | TS picks it from `facts.art`: the first media in `[cover, title, screenshot]` order that the keeper (else any copy) has, and passes it explicitly; with no art at all it asks for `cover` (the libretro fallback). The slot shows a caption (`Captura` / `Pantalla de título`) when it is not a cover. | A profile whose device shows only snaps or titles would otherwise show an empty slot. The bytes carry no media header, so the caller must already know which media it asked for. |
| D6 | Copy thumbnail when? | Only when the copy has art in the cover's media **and** it differs from the group cover (D7). Otherwise only the group cover shows. Tray thumbnails are 32 px wide, loaded only for mounted rows. | Repeating the same image on every row is noise; a different image (e.g. a Japanese box) is exactly the signal that helps decide. |
| D7 | Hash art at plan time? | **No.** `MemberFacts.art` lists present slots as `{ media, path, size }` (size from one `fs::metadata` per art file found; `DirListings` has names only). Same path, or same `(media, size)`, counts as the same image; otherwise different. No byte comparison in JS. | Hashing every image at plan time costs I/O on 22k-file libraries for a cosmetic decision, and comparing bytes in the webview would load the very image we are deciding whether to load. A rare equal-size different image shows no thumbnail, which is harmless. |
| D8 | Format label | Pure TS `formatOf(unit)` over `UnitKindView` (`single zip arcade disc-set chd image multi-disc`) + the primary's extension (read with the existing `fileName()`, both separators): `zip` kind → `ZIP`/`7Z`/`RAR`/… by extension; `disc-set` → `CUE/BIN`, `GDI` or `CCD/IMG`; `chd` → `CHD`; `image` → `PBP`/`ISO`/`CSO`/`RVZ`; `multi-disc` → `M3U` + disc count; `single` → the extension uppercased; `arcade` → `ZIP` or `7Z` plus a localised «arcade» word (`dedupe.format.arcade`). | Derivable from what the view already sends; no core change. |

| D10 | Save detail | `MemberFacts.saves: { count, last_ns }` from `UnitFacts.saves` (real saves only; blank and all-`0xFF` saves already excluded) and `MemberFacts.played: { count, last }` from `UnitFacts.played` when the profile reads a game list. | D12 | Keyboard | Keep ↑↓ (pick within a game), Tab, X (leave this game alone), ⌘R/Ctrl+R (look again). | D13 | Animation | One illustrated moment: **the set-aside**. It reuses brand objects (slot, shelf rule, Manila tab) like the landing's illustrated hero, and it is driven by real progress events, not a loop. |

| D15 | Settings link | **None on this branch.** 1.6 owns «Ajustes de Duplicados» from this screen. | Do not restructure Settings here (owner instruction), and avoid two branches adding the same link and key. |

## 7. UX and UI design

### 7.1 Design plan (frontend-design pass)

**Subject.** A collector's shelf (brand §1). The duplicates screen is the moment of tidying a shelf: two boxes of the same game side by side, you pick one, the other goes into a labelled folder. The memorable thing is **the cover beside the copies and the folder they drop into**; everything else stays quiet.

**Color** (existing tokens only, no new values):

| Role | Token | Hex (light) | Use here |
|---|---|---|---|
| Paper | `--cr-bg` / `--cr-surface` | `#f2f3ef` / `#fbfbf9` | Page, group card |
| Shelf | `--cr-surface-raised` + Buckram cap `--cr-primary` | `#ffffff` / `#0e5e6f` | The keeper row only |
| Tray | `--cr-surface-sunken` | `#e7e9e3` | Set-aside rows: visibly "lower" than the shelf |
| Ink | `--cr-text` / `--cr-text-secondary` | `#1b1e1b` / `#535a52` | Names / facts |
| Tag | `--cr-manila` + `--cr-manila-fg` | `#e6c171` / `#2a2111` | Only the `_Duplicados` folder tab in the scene and the "Tu elección" chip (brand: Manila is a tab, < 2 % of screen) |
| States | `--cr-warning(-bg)`, `--cr-info(-bg)`, `--cr-border-strong` | | Conflict, other version, report-only |

Every text/background pair above is checked at ≥ 4.5:1 in light and dark (`pnpm tokens:check` covers the token pairs; the tray's facts use `--cr-text-secondary` on `--cr-surface-sunken`). The skipped state dims covers and chips, **not** text, so tray text never drops below contrast. Edges are real `border`s, not `box-shadow`, so they survive `forced-colors: active` (Windows High Contrast), where the text stamp carries the state.

**Type.** Body Atkinson Hyperlegible Next 13/14 px; **game title** in Archivo wdth 75 wght 700 at 17 px (the box-label face, used today only for headings, so the game reads as the object); file names, sizes, dates, region codes and counts in Atkinson Hyperlegible Mono (the repo's rule: numbers in mono). Sentence case everywhere; no all-caps labels except region codes, which are codes, not labels.

**Layout.** Left aligned. Per game:

```
┌────────────────────────────────────────────────────────────────┐
│ ┌──────┐  Tetris                                 [Otra versión] │  ← head: cover slot 72×96, title, state stamp
│ │cover │  Game Boy · DMG-TRA                                    │     (serial in mono)
│ │ 3:4  │ ┃(1)● Tetris (World) (Rev 1).gb         Se queda       │  ← shelf: Buckram cap, raised
│ └──────┘ ┃    WLD  Rev 1  En   GB · 32 KiB · 12 mar 2024  ⌕     │     tags, facts, reveal
│          ┃    [Región] Se queda: región preferida (Mundo)…      │     rule chip + why
│          ├──────────────────────────────────────────────────────┤
│          │ (2)○ Quedarme con esta  Tetris (Japan).gb  ▫cover    │  ← tray: sunken, indented
│          │    JPN  GB · 32 KiB · 2 ene 2023  Partida: hace 3 d ⌕│
│          │    → _Duplicados/ROMS/GB/Tetris (Japan).gb           │
│          └──────────────────────────────────────────────────────┘
│  ☐ No tocar este juego                                          │
└────────────────────────────────────────────────────────────────┘
```

The cover column spans the shelf and tray, so the eye goes cover → title → shelf → tray. At widths under 640 px the cover drops above the title at 48×64 and the facts wrap under the name. The window's minimum width and 200 % zoom must not clip the reveal button or the chips (they wrap).

**States** (stamp on the head, plus a left edge on the card; text always present, color never alone):

| State | Stamp | Edge | Rows |
|---|---|---|---|
| Acts (exact) | none | none | as above |
| Other format / other version | relation badge (existing, `info` tone for version) | 3 px `--cr-info` | tray rows show their own relation |
| Report only | «Solo informe» + reason in tooltip | 1.5 px dashed `--cr-border-strong` (the "missing slot" outline: nothing will move) | no radios, «Se queda también» |
| Conflict | «Partidas distintas» (`warning`) | 3 px `--cr-warning` | every copy with its save date side by side, reveal on each save |
| Skipped by you | «No se toca» | dashed | tray dimmed to 60 % opacity (existing) |

**Motion.**
- Existing: cap slide on pick (`--cr-duration-base`, `standard`), kept.
- New, D13: the set-aside scene, durations `slow` (240 ms lift + slide) and `slower` (400 ms drop, `ink` easing), one slot at a time, never faster than the events (coalesced to at most 4 per second; above that the folder counter ticks and slots go in batches). `spring` is not used (brand: never on apply).
- Cover load: the dashed outline draws in, then the image fades in over `fast`. No hover lifts, no entrance animations on groups.
- `prefers-reduced-motion`: all of the above collapse to 0 ms (`useReducedMotion`, hoisted; the CSS also has `@media (prefers-reduced-motion: reduce)` blocks, as `dedupe.css` does today). macOS and Windows expose the OS setting to the webview; on Linux WebKitGTK it follows the GTK `gtk-enable-animations` setting.

## 9. Data flow

1. **Plan**: `dedupe_plan` → core `plan_dedupe` builds `UnitFacts` (unchanged cost) → `Member.facts` → `DedupePlanView` (Tauri flattens) → `dedupeStore.plan`. Regroup and set-keeper return a view with the same facts (facts belong to units, not to the keeper choice; only the rule chip and why change).
2. **Cover**: a group row mounts (windowed) → `useDedupeArt(planId, group.id, null, preferredMedia)` → `dedupe_art` → Rust resolves from the kept plan → bytes → object URL in `artCache` (LRU, revoked on evict) → `GroupCover`. A member's own thumbnail asks with `member = id` only when `facts.art` shows a slot with a size different from the group cover's (D7).
3. **Reveal**: click / chord → `dedupeStore.reveal(currentPath(member, job))` (D1) → `reveal_path` → `revealable` checks the path is inside a known root or quarantine → `opener.reveal_item_in_dir`. Errors set the store's `error` (existing banner, `outside-library` / `not-found` copy) without changing `status`. Organise uses its own store's reveal with the same command.
4. **Apply**: unchanged command; `dedupe-progress` events with `phase: 'apply'` drive `SetAsideScene` (`done/total`), `dedupe-changed` ends it; the result shows the reveal-folder button.
5. **Keys**: list-level handler for J/K (focus model: "focused game" = the group containing `document.activeElement`; J from outside the list is not handled), window handler for ⌘↩; group-level handler for 1–9 and reveal.

## 10. Edge cases and failure modes

| Case | Behaviour |
|---|---|
| No catalogue match and no tags in the file name | No tag chips; facts line still shows format, size, date. `tags_from` absent. |
| Catalogue name and file name disagree on region | Catalogue wins (it is content-backed); tooltip says «Del nombre del catálogo». A `[b]` or hack mark only in the file name still shows, marked «Del nombre del archivo». |
| Region word not in `Region` (`Russia`, `Latin America`, `Scandinavia`) | Shown as an `other` tag as written, not dropped. |
| Multi-region `(USA, Europe)` | Two chips in catalogue order. More than 3 regions: first 3 + «+2» chip with the rest in its tooltip. |
| Multi-disc / CUE/BIN set | Format from the primary (`CUE/BIN`, `M3U`); size is the unit total (already); date is the newest file. |
| Arcade set | `ZIP (arcade)`; tags usually empty (MAME names have none). |
| Copy has art but the plan was regrouped / expired | `dedupe_art` → `art-missing` → missing slot, no toast. A regroup returns a new view whose `facts.art` is current. |
| Art file unreadable, not an image, over 20 MiB, or a symlink out of the library | `art-missing` (outside-root is logged at `warn`, the rest at `debug`). |
| Library on a removable volume that is pulled | `dedupe_art` → `art-missing`; reveal returns `not-found` → existing banner; nothing else changes. |
| Copy art taken by the keeper on apply (`art_leaves`) or travelling with the copy | After apply the plan is not re-read for art; the result screen shows no covers. |
| Copy deleted outside Coverly between plan and reveal | `revealable` falls back to the nearest existing folder (existing behaviour). |
| Path outside the library from a tampered webview | `revealable` refuses with `outside-library` (existing; tested). `dedupe_art` takes ids only. |
| Trash mode | No reveal-folder button after apply (Trash location is OS-specific); per-copy reveal before apply still works; after apply the moved copies have no reveal. |
| Reveal a tray copy after apply | Reveals `dest` in the quarantine (the job's quarantine is a known folder); after undo, its original place. |
| Linux without a FileManager1 D-Bus service | The opener falls back to opening the parent folder; label «Mostrar en la carpeta» stays true. |
| Windows paths | Rust compares with `Path::starts_with` (components). TS never compares paths; it only shows `fileName()` (already handles both separators). |
| Thousands of groups | Covers load only for mounted rows (windowed); the LRU caps memory (existing `artCache` limit). Facts add ~150–300 bytes per member to the view (art paths included). The libretro index for a system is built once per kept plan, not per group. |
| Very fast apply (hundreds per second) | Scene coalesces to ≤ 4 slots per second and shows the true counter. |
| Reduced motion | Scene static; counter updates; cap jump instant. |
| Keyboard 1–9 with more than 9 copies | Copies 10+ have no number key (arrows still reach them); rows above 9 show no number badge. |
| Typing in the options (none today, the search lands with 1.6) | All single-key shortcuts ignore `isTyping` targets. |
| Screen reader in browse mode | J/K/1–9 only act with focus inside the groups list (forms/focus mode on the radios); in browse mode the reader keeps its own quick-nav letters. |
| Organise proposal (`pickable={false}`) | Tags, facts and reveal show; covers, numbers and pick keys do not. Pile copies reveal through `reveal_path`, whose known folders now include the kept Organise plans' source and target (D1). |
| Installed users upgrading | Plans are kept in memory only; journals and exported plans from older versions read back with empty facts (D14); no settings, cache schema or capability change. |
