# Coverly ROMs — Duplicates screen polish (Design Spec)

> Status: **Draft for review** · Date: 2026-10-26 · Owner: Miguel Angel Esparza Calero (MAECLY)
> Roadmap item: TODO.md **1.5. Mejora de la interfaz de Duplicados**.
> Builds on [`2026-10-18-duplicates-design.md`](2026-10-18-duplicates-design.md) (the planner, the "shelf and tray" screen, §11). Nothing in the planner's grouping, keeper rules or apply changes here: this item adds **facts the planner already knows** to the plan view, **one read-only command** for covers, and a **visual and keyboard pass** over the screen.
> Branch: `feat/dedupe-screen-polish`. The settings reorganisation (TODO 1.6) runs in parallel on `feat/settings-tabs`; this branch does not touch the settings screen.

## 1. Purpose

The duplicates screen tells you the truth, but it reads like a list of file names. When two copies are the same game, what you need to decide is the **region**, the **revision**, whether a copy has **your save**, what **format** it is in and what it **looks like**. Today the screen shows the file name, a size, a "Se queda" badge and one sentence of why. You cannot see the cover, you cannot open the copy in Finder before you decide, and you cannot tell at a glance why the shelf holds what it holds.

This item makes each copy readable at a glance and the screen pleasant to work through with the keyboard, without changing what Coverly decides or moves.

## 2. The owner's asks (verbatim from TODO.md 1.5)

> La pantalla «estante y bandeja» da la información, pero se queda simple. Mejoras:
>
> - **Mostrar en Finder / Explorador / gestor de archivos** para cada copia (la que se queda y las que se apartan) y para la carpeta `_Duplicados/` tras aplicar. En Tauri, `tauri-plugin-opener` (`revealItemInDir`) cubre macOS, Windows y Linux; texto según el sistema: «Mostrar en Finder», «Mostrar en el Explorador», «Mostrar en la carpeta».
> - **Etiqueta de región** en cada copia (USA, Europe, Japan, World…, con su bandera o código), sacada del nombre del catálogo o de las etiquetas del nombre del archivo (`NameTags`). Cuando las copias son el mismo juego, la región es lo que más ayuda a decidir; también revisión (`Rev 1`), idioma (`En,Fr,De`) y marcas de volcado (`[!]`, `[b]`, hack, traducción) como etiquetas.
> - **Portadas**: hoy la pantalla no muestra ninguna. Enseñar la portada de cada grupo (y de cada copia si tiene la suya), reutilizando las de la biblioteca y las de libretro-thumbnails; con hueco de portada claro cuando falte.
> - Más detalle por copia: tamaño, formato (zip, 7z, CHD, CUE/BIN), fecha de modificación, si tiene partida guardada y de cuándo, y por qué regla se eligió la que se queda.
> - Repaso visual con el skill de diseño: jerarquía entre el juego, la copia que se queda y las apartadas; estados (conflicto, solo informado, otra versión) más visibles; atajos de teclado para elegir copia y aplicar; animación al apartar en la línea de la landing.

The owner also said, for this run: reveal must use a **narrow** permission (only paths inside the library or the quarantine, never an arbitrary path from the webview) and be mocked in the browser backend; illustrated animations in the landing's style are welcome.

## 3. Goals and non-goals

### Goals

1. **Reveal** every copy (keeper and tray, including conflict copies and report-only copies) and the quarantine folder after apply, with an OS-specific label.
2. **Tags** on every copy: region(s), revision, languages, release class (beta, proto, demo, sample), dump flags (`[!]` verified, `[b]` bad, `[o]` overdump, `[a]` alternate) and modification (hack, translation, trainer, fixed, pirate, unlicensed), each marked with where it came from (catalogue name or file name).
3. **Covers**: one cover per group (the keeper's, else the first copy that has one, else a cached libretro thumbnail of the catalogue name), plus a small thumbnail on a copy that has **its own** art different from the group cover. A clear missing-art slot (brand §2 "Missing" slot) when there is none.
4. **Facts per copy**: size, format, modification date, save (present, how many, last written), and a **rule chip** naming the rule that put the keeper on the shelf.
5. **Visual pass**: a clear hierarchy game → kept copy → set-aside copies; conflict, report-only and other-version states visible without reading; keyboard shortcuts to move between games, pick a copy, reveal and apply; one calm illustrated set-aside animation.
6. The same `DupGroup` keeps working in the Organise proposal (`pickable={false}`), where the new facts and covers also show.

### Non-goals

- Changing grouping, keeper rules, confidence, apply, undo or the plan format version.
- Downloading anything to show a cover. Covers come from disk (library art) or the existing downloaded-art cache, offline only.
- Restructuring Settings or moving the duplicates options (TODO 1.6, parallel branch). The screen may link to "Ajustes de Duplicados" once that tab exists; until then it links to the current Library section, as today.
- Flag emoji. See D3.
- A new screen or route. Everything happens inside `DuplicatesScreen`, `DupGroup` and its rows.

## 7. UX and UI design

### 7.1 Design plan (frontend-design pass)

**Subject.** A collector's shelf (brand §1). The duplicates screen is the moment of tidying a shelf: two boxes of the same game side by side, you pick one, the other goes into a labelled folder. The memorable thing is **the cover beside the copies and the folder they drop into**; everything else stays quiet.

**Color** (existing tokens only, no new values):

| Role | Token | Hex (light) | Use here |
|---|---|---|---|
| Paper | `--cr-bg` / `--cr-surface` | `#f2f3ef` / `#fbfbf9` | Page, group card |
| Shelf | `--cr-surface-raised` + Buckram cap `--cr-primary` | `#ffffff` / `#0e5e6f` | The keeper row only |
| Tray | `--cr-surface-sunken` | `#e7e9e3` | Set-aside rows: visibly "lower" than the shelf |
| Ink | `--cr-text` / `--cr-text-secondary` | `#1b1e1b` / `#535a52` | Names / facts |
| Tag | `--cr-manila` + `--cr-manila-fg` | `#e6c171` / `#2a2111` | Only the `_Duplicados` folder tab in the scene and the "Tu elección" chip (brand: Manila is a tab, < 2 % of screen) |
| States | `--cr-warning(-bg)`, `--cr-info(-bg)`, `--cr-border-strong` | | Conflict, other version, report-only |

**Type.** Body Atkinson Hyperlegible Next 13/14 px; **game title** in Archivo wdth 75 wght 700 at 17 px (the box-label face, used today only for headings, so the game reads as the object); file names, sizes, dates, region codes and counts in Atkinson Hyperlegible Mono (the repo's rule: numbers in mono). Sentence case everywhere; no all-caps labels except region codes, which are codes, not labels.

**Layout.** Left aligned. Per game:

```
┌────────────────────────────────────────────────────────────────┐
│ ┌──────┐  Tetris                                 [Otra versión] │  ← head: cover slot 72×96, title, state stamp
│ │cover │  Game Boy · DMG-TRA                                    │     (serial in mono)
│ │ 3:4  │ ┃(1)● Tetris (World) (Rev 1).gb         Se queda       │  ← shelf: Buckram cap, raised
│ └──────┘ ┃    WLD  Rev 1  En   GB · 32 KiB · 12 mar 2024  ⌕     │     tags, facts, reveal
│          ┃    [Región] Se queda: región preferida (Mundo)…      │     rule chip + why
│          ├──────────────────────────────────────────────────────┤
│          │ (2)○ Quedarme con esta  Tetris (Japan).gb  ▫cover    │  ← tray: sunken, indented
│          │    JPN  GB · 32 KiB · 2 ene 2023  Partida: hace 3 d ⌕│
│          │    → _Duplicados/ROMS/GB/Tetris (Japan).gb           │
│          └──────────────────────────────────────────────────────┘
│  ☐ No tocar este juego                                          │
└────────────────────────────────────────────────────────────────┘
```

The cover column spans the shelf and tray, so the eye goes cover → title → shelf → tray. At widths under 640 px the cover drops above the title at 48×64 and the facts wrap under the name.

**States** (stamp on the head, plus a left edge on the card; text always present, color never alone):

| State | Stamp | Edge | Rows |
|---|---|---|---|
| Acts (exact) | none | none | as above |
| Other format / other version | relation badge (existing, `info` tone for version) | 3 px `--cr-info` | tray rows show their own relation |
| Report only | «Solo informe» + reason in tooltip | 1.5 px dashed `--cr-border-strong` (the "missing slot" outline: nothing will move) | no radios, «Se queda también» |
| Conflict | «Partidas distintas» (`warning`) | 3 px `--cr-warning` | every copy with its save date side by side, reveal on each save |
| Skipped by you | «No se toca» | dashed | tray dimmed to 60 % opacity (existing) |

**Motion.**
- Existing: cap slide on pick (`--cr-duration-base`, `standard`), kept.
- New, D13: the set-aside scene, durations `slow` (240 ms lift + slide) and `slower` (400 ms drop, `ink` easing), one slot at a time, never faster than the events (coalesced to at most 4 per second; above that the folder counter ticks and slots go in batches). `spring` is not used (brand: never on apply).
- Cover load: the dashed outline draws in, then the image fades in over `fast`. No hover lifts, no entrance animations on groups.
- `prefers-reduced-motion`: all of the above collapse to 0 ms (existing `useReducedMotion`).

## 9. Data flow

1. **Plan**: `dedupe_plan` → core `plan_dedupe` builds `UnitFacts` (unchanged cost) → `Member.facts` → `DedupePlanView` (Tauri flattens) → `dedupeStore.plan`. Regroup and set-keeper return a view with the same facts (facts belong to units, not to the keeper choice; only the rule chip and why change).
2. **Cover**: a group row mounts (windowed) → `useDedupeArt(planId, group.id, null, preferredMedia)` → `dedupe_art` → Rust resolves from the kept plan → bytes → object URL in `artCache` (LRU, revoked on evict) → `GroupCover`. A member's own thumbnail asks with `member = id` only when `facts.art` shows a slot with a size different from the group cover's (D7).
3. **Reveal**: click / chord → `dedupeStore.reveal(member.unit.primary)` → `reveal_path` → `revealable` checks the path is inside a known root or quarantine → `opener.reveal_item_in_dir`. Errors set the store's `error` (existing banner, `outside-library` / `not-found` copy).
4. **Apply**: unchanged command; `dedupe-progress` events with `phase: 'apply'` drive `SetAsideScene` (`done/total`), `dedupe-changed` ends it; the result shows the reveal-folder button.
5. **Keys**: screen-level handler for J/K and ⌘↩ (focus model: "focused game" = the group containing `document.activeElement`, else the first visible); group-level handler for 1–9 and reveal.

## 10. Edge cases and failure modes

| Case | Behaviour |
|---|---|
| No catalogue match and no tags in the file name | No tag chips; facts line still shows format, size, date. `tags_from` absent. |
| Catalogue name and file name disagree on region | Catalogue wins (it is content-backed); tooltip says «Del nombre del catálogo». |
| Multi-region `(USA, Europe)` | Two chips in catalogue order. More than 3 regions: first 3 + «+2» chip with the rest in its tooltip. |
| Multi-disc / CUE/BIN set | Format from the primary (`CUE/BIN`, `M3U`); size is the unit total (already); date is the newest file. |
| Arcade set | `ZIP (arcade)`; tags usually empty (MAME names have none). |
| Copy has art but the plan was regrouped / expired | `dedupe_art` returns `None` → missing slot, no error. |
| Art file unreadable or not an image | `None`; logged at `debug`. |
| Library on a removable volume that is pulled | `dedupe_art` returns `None`; reveal returns `volume-gone`/`not-found` → existing banner; nothing else changes. |
| Copy deleted outside Coverly between plan and reveal | `revealable` falls back to the nearest existing folder (existing behaviour). |
| Path outside the library from a tampered webview | `revealable` refuses with `outside-library` (existing; tested). `dedupe_art` takes ids only. |
| Trash mode | No reveal-folder button after apply (Trash location is OS-specific); per-copy reveal before apply still works. |
| Windows paths | Rust compares with `Path::starts_with` (components). TS never compares paths; it only shows `fileName()` (already handles both separators). |
| Thousands of groups | Covers load only for mounted rows (windowed); the LRU caps memory (existing `artCache` limit). Facts add ~100 bytes per member to the view. |
| Very fast apply (hundreds per second) | Scene coalesces to ≤ 4 slots per second and shows the true counter. |
| Reduced motion | Scene static; counter updates; cap jump instant. |
| Keyboard 1–9 with more than 9 copies | Copies 10+ have no number key (arrows still reach them); rows above 9 show no number badge. |
| Typing in the options (none today, the search lands with 1.6) | All single-key shortcuts ignore `isTyping` targets. |
| Organise proposal (`pickable={false}`) | Covers, tags, facts and reveal show; numbers and pick keys do not. Pile copies reveal through `reveal_path`, whose known folders include the plan root (the pile). |
