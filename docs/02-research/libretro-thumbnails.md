Corrections:
(1) The CloudFlare part is only a README statement. Today's direct response comes from Apache with no cf-ray or CloudFlare headers, and DNS resolves to 5.9.202.203.
(2) Server folder names do NOT always equal the umbrella checkout paths. The server has 'Atari - 8-bit' and 'NEC - PC-8001 - PC-8801' where the repo has 'Atari - 8-bit Family' and 'NEC - PC-88'. Always build the system list from the live server root.
(3) The docs order for local flexible matching is ROM file name, then game name, then short name. The code tries the label (database name) first, then the full file name, then the short name. The download order is FULL, then STD, then SHORT, and FULL is skipped unless playlist_use_filename is on.
(4) The forum quotes come from different posters. The yard.zip / 10 Yard Fight example is a playlist excerpt from user jducifuentes, not a maintainer's statement.

New findings:
- mini-scraper's stripMetadata keeps the '.png' suffix on candidates ('X (USA).png' becomes 'X .png'). Fuzzy and Levenshtein scoring therefore run against strings that still carry ' .png'.
- Exact and substring matching in mini-scraper are case-sensitive.
- RetroArch has a special case for single-entry playlists, which go straight to STD_NAME.

## Lessons for Coverly ROMs

- Build the list of systems from the live thumbnails.libretro.com root listing, not from the umbrella .gitmodules. Names differ: the server has 'Atari - 8-bit' and 'NEC - PC-8001 - PC-8801', the repo has 'Atari - 8-bit Family' and 'NEC - PC-88'. Keep a separate map from server folder to GitHub repo for the raw.githubusercontent fallback.
- Primary source: https://thumbnails.libretro.com/<System>/<Named_Type>/<sanitised>.png, percent-encoding each segment. Fallback: raw.githubusercontent.com/libretro-thumbnails/<repo with '_' for spaces>/master/... . Store ETags per host, because the two hosts' ETags differ even when the bytes are identical.
- Do not rely on a CDN. The server currently answers directly from Apache on a single IP. Keep concurrency low (4-6), use backoff, and reuse each listing for every lookup.
- Parse the Apache listing hrefs, drop the '?C=' sort links, URL-decode the names, and cache the index on disk per system and type with a TTL of about 2 days, matching the README's cron cadence.
- Sanitise exactly as RetroArch does: & * / : ` " < > ? \ | become '_'. mini-scraper misses the backslash.
- Before tag-stripping or fuzzy scoring, remove the '.png' extension from candidates. mini-scraper's stripMetadata leaves ' .png' on candidates, which skews its scores.
- Make all matching case-insensitive on a normalised key while keeping the original filename for the download. mini-scraper's exact and substring stages are case-sensitive.
- Try matches in RetroArch's order for the local thumbnails layout (label, then filename, then short name). Because the docs and code disagree on order, prefer the most specific exact hit and only then fall back to fuzzy.
- Rank variants deterministically by region and tags. mini-scraper's non-AI path picks the first variant in alphabetical listing order (for example Europe before USA).
- Arcade needs DAT translation from short name to description via libretro-database metadat/mame and metadat/fbneo-split. mini-scraper has none.
