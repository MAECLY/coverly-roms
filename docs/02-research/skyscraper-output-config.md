I read it with grep and sed and executed nothing from it. I also re-fetched the external URLs. Most claims hold. Five need corrections. (1) The cache-ID filename fallback list contains no m3u. The comparison is case-sensitive. The exact list is uae, cue, conf, sh, svm, scummvm, mds, zip, 7z, gdi, ml, bat, au3, po, dsk, nib. (2) Raw copies are not always PNG. Composited outputs are .png, but resource types that artwork.xml does not define go through AbstractFrontend::copyMedia, which takes the extension from the mime type (jpg or png). The EmulationStation baseline supportedMedia() does NOT include COVER, so ES only gets covers when artwork.xml outputs one. (3) Media subfolders are hardcoded by each frontend class. config.coversFolder = frontend->getCoversFolder() and no config key overrides it. As a result no frontend can produce a flat Roms/<SYS>/Imgs/<rom>.png. The closest results are ES <mediaFolder>/covers/<rom>.png, Batocera <mediaFolder>/images/<rom>-thumb.<ext> and RetroArch Named_Boxarts/<title>.png. A handheld layout therefore needs post-processing or a wrapper. (4) In peas.json, 'aliases' are extra search terms for scraping sites. They are not used to detect folders, because the platform is always given explicitly with -p. (5) The handheld wrapper URL should be the canonical github.com/topics/miyoo-mini, and the repo is y-muller/onionscraper. Its README shows it uses frontend=emulationstation plus custom artwork-onionscraper*.xml files and generates miyoogamelist.xml. A small doc/code mismatch also exists: CONFIGINI says cached art is converted to PNG, but cache.cpp saves JPG (jpgQuality) unless the image has alpha or is a screenshot. Additions: Batocera's default artwork.xml is empty, so media is copied as-is. ES-DE honours $ESDE_APPDATA_DIR. RetroArch media defaults to ~/.config/retroarch/thumbnails/<db_name>. fanart, manual and backcover are never resized. onlymissing is checked before the per-module cache.

## Lessons for Coverly ROMs

- Use the two-phase model: a content-addressed art cache, then a separate write-to-layout step. This lets users re-target output profiles without downloading again.
- Key the cache by content hash with a filename-hash fallback, but compare extensions case-insensitively (Skyscraper's case-sensitive suffix check is a bug to avoid). Decide m3u/cue/chd handling on purpose. Keep a path+mtime+size quickid memo.
- Make the output-profile subfolder and filename pattern fully configurable (e.g. '{romdir}/Imgs/{basename}.png', '{media}/covers/{basename}.png', '{media}/images/{basename}-thumb.png', 'Named_Boxarts/{sanitizedTitle}.png'). Skyscraper hardcodes these per frontend, which is exactly why handheld users need wrappers.
- Make the 'has cover' check profile-aware. Accept png/jpg/jpeg/webp twins, and for Batocera match the -thumb postfix. For RetroArch, match the sanitized title, not the ROM basename.
- Normalize the output format per profile. Skyscraper's raw copies keep the source's jpg or png extension, while composites are png, so a library can end up mixed. Handheld firmware (Onion/MinUI) usually needs PNG at a fixed size, so convert explicitly.
- Auto-detect the console from folder names with our own alias table (GB, GBC, FC, SFC, MD, PS, ...) that users can edit. Skyscraper has no such detection (peas.json aliases are only search terms, and -p is explicit).
- Default to non-destructive bulk runs: skip existing, dry-run preview (like pretend), back up any gamelist, and offer an 'only missing' mode.
- Ship a missing-cover report export plus a 'retry only these' option, mirroring report:missing=cover and --includefrom.
- Keep region priority (eu, us, wor, jp...) with an inline No-Intro tag merge, so the best libretro-thumbnails variant is chosen.
- Offer a per-profile resize and fit mode (keep, keepexpand/pad, as in the 340x480 extended to 640x480 Garlic recipe), and skip resizing for large non-cover media.
- Mirror the ROM subfolder tree in the browser and in outputs, as ES-DE does, and show folders as nodes, as addFolders does.
- For v1, ship only raw cover pass-through. Compositing is optional and comes later.
