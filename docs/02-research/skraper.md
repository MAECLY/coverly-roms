# Skraper (skraper.net): how the leading Windows ROM scraper works end to end (verified dossier)

> Generated from research workflow `wf_46f73971-0a2` (2026-10-15): one research agent + one skeptical verifier per topic. Claims: 20 verified, 8 corrected, 2 unverifiable.

## Summary

I checked every claim against a live fetch of skraper.net (saved to /private/tmp/claude-501/-Users-miguelangelesparzacalero-Documents-GitHub/35b7c020-f2ae-412f-b757-99c24a9a498b/scratchpad/research-clones/verify-skraper/index.html), ImageComposition.xsd, the ScreenScraper webapi2 page, a fresh clone of ebzero/garlic-onion-skraper-mix, the Onion, Joey and RetroDeck guides, and the RetroPie forum JSON API (the HTML pages sit behind a cookie wall). I also read, without running, the strings and text files of the official Skraper-1.4.2.7z, extracted to .../verify-skraper/bin/x. Most claims hold. Four are corrected and the rest are verified, apart from a few unverified side details listed below.

Corrections:
1. **Version.** The current version is 1.4.2, not 1.4.1. The HTML hard-codes 1.4.1 links, but js/app-version.js rewrites them from /update/update.json, which says UserVersion 1.4.2 (released 2026-08-18).
2. **Updates.** Skraper DOES have a built-in auto-updater. SkraperUI.exe requests https://www.skraper.net/update/update.json and treats the update as Optional or Mandatory. It downloads the archive, verifies it, backs up the old .exe/.dll files and rolls them back if something fails, then unzips the new files and cleans up the previous version. The 1.4.1 release notes add "Optionnal updates can now be skiped on starting." The dossier said no updater exists, which is wrong.
3. **Region evidence.** The cited forum posts were wrong. The real sources are post 169973 for the region claim and posts 99927 and 160160 for the hashing caveat.
4. **Resize and cleanup settings.** The "all handheld guides" generalisation is wrong. Joey's guide sets neither resize nor cleanup. Onion's FAQ sets resize, and ebzero's README sets "Cleanup output folder".

Additional findings:
- 1.4.1 ships experimental installer scripts for Ubuntu, Fedora and macOS that install mono (plus libgdiplus on macOS, via Homebrew).
- SkraperUI.exe.config targets .NETFramework v4.8, while the site tells users to install 4.8.1.
- The UI has a matching-method selector whose visible default is "crc, then filename".
- The library treats zip, 7z, rar, gz, xz and tar as archives.
- Requests go to https://api.screenscraper.fr/api2/{0}.php with retry and back-off.
- Many 3/4/5-image mix XMLs ship in a Mixes/ folder.
- The site's feature list calls user mixes "JSON definition files", but the shipped mixes and the XSD are XML.

## Lessons for Coverly ROMs

- Skraper's updater design is worth copying, with signed artifacts on top. It uses a static manifest (update.json with Version, UserVersion, a Mandatory flag and Url), checks it at startup, and lets users skip optional updates. It downloads, verifies the archive, backs up the old binaries with rollback, swaps them in, and logs to Update.Logs.txt. For Coverly, use GitHub Releases plus the Tauri updater (a latest.json manifest with signatures) or electron-updater, and add a 'mandatory' flag and a 'skip this version' option.
- Make the matching method a user setting with a visible default, as Skraper does with 'crc, then filename'. Offer hash only, hash then name, and name only. Compute expensive hashes only when the chosen method needs them, which is what Skraper's 1.4.2 'Calculate CRC only if selected' fix does.
- Hash the content inside an archive, not the archive itself. Read the CRC32 from ZIP headers or the MD5 from 7z headers when they are present. Treat zip, 7z, rar, gz, xz and tar as archives, as Skraper does. For multi-disc games, use the .m3u or .cue as the game entry and ignore side files (.bin, .sub, .ccd).
- The default source, libretro-thumbnails, needs no account and has no quota. If ScreenScraper is added later as an advanced source, read ssuserInfos to show the user's maxthreads and quotas, and handle 429 (back off), 430 (daily quota reached) and 431 (too many not-found results today) with clear messages. Use retry with growing waits, as Skraper does.
- Auto-detect systems with a recursive scan and a large table of folder-name aliases. Show the detected system count, and offer '+ add system' and per-system folder remapping.
- Make output paths templates ({ROMROOT}/{SYSTEMDIR}/{ROMNAME}) with presets for Onion, Garlic and stock Anbernic: '{SYSTEMDIR}/Imgs/{ROMNAME}.png', PNG, at most 250x360, capital I. Add presets for ES-DE, Batocera/Recalbox (media plus gamelist.xml) and muOS.
- Provide resize settings (width, height, keep ratio, pad to canvas) and test them well, since resizing was broken across several Skraper versions (1.4.1 and 1.4.2 both fix it). Default to the target device's size limits.
- Keep a cache keyed by content hash so the app downloads once and applies many times. Store identical images once, and make 'hash in filename' opt-in, as Skraper did in 1.4.1.
- Skip ROMs that already have art by default so runs can resume (Joey relies on this). Offer 'force overwrite' and 'clean orphaned images' with a dry-run preview first. For gamelist.xml, offer explicit modes: backup then update, backup then overwrite, update without backup, and don't touch.
- Use a region priority list (USA > World > Europe > Japan) with a 'use the ROM's own region tag first' toggle. Apply it when choosing between libretro-thumbnails name variants.
- Composition (box plus screenshot plus logo) can come later. If it is added, use one documented format: Skraper's site says JSON while its schema is XML, which is confusing. Copy the fallback chain pattern (Screenshot > Title > Wallpaper > Text).
- Ship native builds for each OS. Skraper on Linux and macOS needs mono and libgdiplus through shell installer scripts, has no native Mac app, and asks users for WINE or CrossOver plus Rosetta. Coverly can beat that with signed .dmg, .msi/.exe and AppImage/.deb builds from one CI pipeline, and should stay open source.
- Add per-game manual fixes (search the index by name, pick from candidates, or drop in a local image). Skraper does not document this well, so it is a usability advantage for Coverly.
