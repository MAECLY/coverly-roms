Important additions:
- muOS maps a ROM folder to a catalogue through catalogue= in MUOS/info/assign/<system>/global.ini.
- muOS ignores subfolders inside box/ and preview/.
- muOS Folder-catalogue matching is case-insensitive.
- Onion's config.json also has hidebios and shortname flags.
- Batocera writes gamelist.xml at the ROM root by default.
- Pegasus searches only PNG/JPG and has aliases for each asset.

## Lessons for Coverly ROMs

- Layout profiles must mark whether art mirrors subdirectories: yes for ES-DE and Spruce Imgs; no for Batocera images/ (flat, with stem collisions possible) and muOS box/ (subfolders ignored). Warn the user about stem collisions on flat layouts.
- For muOS, read catalogue= from MUOS/info/assign/<system>/global.ini on the card and use the static mini-scraper table only as a fallback.
- For RetroArch and libretro lookups, try the ROM filename first, then the sanitized title (&*/:`<>?\|" become _), then the title cut at the first '('. Write only PNG unless the user says their RetroArch is newer than 1.19.1.
- Do not force LaunchBox's -01 suffix. Save as <Title>.png or <romname>.png under Images/<Platform>/Box - Front[/<Region>]/ and tell the user to run Tools > Refresh All Images.
- ES-DE systems.txt is an output of ES-DE, but it is still a useful read-only hint for detecting an ES-DE ROM tree.
- Honour Onion's per-system hidebios flag and extlist from Emu/*/config.json when auditing. Skip PORTS/Shortcuts and SCUMMVM/Shortcuts as non-cartridge folders.
- Mark GarlicOS (primary FAQ is 404), TrimUI Brick (top-level Imgs/<SYS>/) and Anbernic stock as community-sourced layouts with editable templates. Do not claim a Smart Pro layout without a source.
- For Batocera/Knulli, create or update <rom root>/gamelist.xml, since that is where ES writes when none exists. Use ./images/<stem>-image.png or -box.png paths and back up the file first.
- Pegasus check: for the boxFront, box_front and boxart2D names, look for PNG or JPG only under media/<title or stem>/.

### Decisions for the profile defaults

- **Disc layouts (spec §8.2): confirmed, unchanged.** anbernic-stock, garlicos, onion and muos stay `Flat` without `.m3u`: Onion and spruceOS never list `.bin` for a disc system (R1-1, R1-3, R1-8), so tracks stay hidden in a flat folder. minui stays `GameFolder` with `.m3u` (R1-13). esde stays `GameFolder` with `.m3u` because it lists `.bin` (R1-14). batocera and retroarch stay `Flat` with a generated `.m3u` for multi-disc games (R1-18, R1-19).
- **Accepted containers (spec §8.3): confirmed.** zip and 7z as-is on every profile except minui, which takes zip only (R1-12). rar, tar and the single-file compressors are extracted everywhere, even where one Drastic build lists `rar` (R1-6): one emulator is not a whole system folder.
- **Disc systems never take an archive as-is**, even where a list has `zip|7z` (Onion `PCECD`, R1-2): a cue/bin set inside an archive is extracted (spec D4).
- **Override (changed from the spec's open row): `psp` takes no archive as-is on any profile.** spruceOS lists none (R1-9) and the PPSSPP core reads none (R1-20). `nds` and `n64` keep the profile's zip/7z (R1-6, R1-9, R1-16).
